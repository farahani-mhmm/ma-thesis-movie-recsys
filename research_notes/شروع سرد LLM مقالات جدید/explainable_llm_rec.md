# Explainable recommendation with LLMs, 2025-2026 papers only (catalogue for a MovieLens + TMDB Top-10-with-reasons practice project)

Scope and conventions
- Only papers first posted/published in 2025 or 2026 are catalogued. Older work is listed only in "Older baselines mentioned".
- Verification labels: **[A]** = arXiv/IJCAI/venue abstract page fetched and read; **[F]** = arXiv HTML full text fetched (summarised by a small model, so numbers should be spot-checked before quoting in the thesis); **[S]** = search snippet only (SciSpace abstract or web-search summary, nothing fetched).
- "Code: none found" means no repository link on the arXiv page or in the fetched text. It does not prove that no code exists.
- Date caveat: SciSpace dates, arXiv ids and arXiv "submitted" dates sometimes disagree (examples are noted inline). All such cases still fall inside 2025-2026.
- Today = 2026-10-30.

## Key Question 1: Which 2025-2026 explanation-generation approaches are simple enough to reproduce with an open HuggingFace model and a small GPU?

### Takeaway
The cheapest faithful designs do not train the LLM at all. They compute the evidence with a conventional model (SHAP on a GBM, an additive linear score, or a graph/rule score) and use a prompt-only LLM to verbalise it (FIRE, FAB-LPR, the IntRS 2025 matrix-factorisation study, the fuzzy-rule + LLM line). End-to-end fine-tuned explainers (Curr-RLCER, XRec successors, RL variants) typically need multi-GPU training, and almost none of the 2025-2026 papers I verified released code. The XRec reproducibility study (open code) and Curr-RLCER (code on GitHub, 3B model) are the only items with a runnable repo among the fine-tuning family.

### Cited Findings
- **FIRE (arXiv 2508.05225, Aug 2025)**: an XGBoost 3-class sentiment predictor on user/item cluster features is explained with SHAP; the top-K features by |SHAP| are mapped back to cluster descriptions and put into a structured prompt. LLM = gpt-4.1-mini via API (feature extraction, cluster naming, generation, judging). Clustering ran on one RTX 4090 (FAISS K-Means, CPU fallback); XGBoost and SHAP ran on CPU. No code link. Weighted F1 0.73 / 0.72 / 0.65 (TripAdvisor / Amazon movies-TV / Yelp). — [FIRE html](https://arxiv.org/html/2508.05225), [abs](https://arxiv.org/abs/2508.05225)
- **Curr-RLCER (arXiv 2604.05341, DASFAA 2026)**: base LLM Qwen2.5-3B-Instruct; training compute 8x RTX 4090, about 12 h per curriculum stage; code at https://github.com/pxcstart/Curr-RLCER (as printed on the arXiv page). — [html](https://arxiv.org/html/2604.05341), [abs](https://arxiv.org/abs/2604.05341)
- **IntRS 2025 user study (arXiv 2509.18980)**: explanations generated purely by prompting DeepSeek-R1-Distill-Llama-70B from an interpretable bounded-simplex matrix-factorisation recommender (BSSMF) on a 100-movie MovieLens-32M subset; inference in fp16 on eight A40 (40 GB) GPUs; code https://github.com/MaximeUM/interpretable-mf-llm-explanations. The prompting recipe is reproducible, but the 70B model is not a single-GPU model. — [html](https://arxiv.org/html/2509.18980v1), [abs](https://arxiv.org/abs/2509.18980)
- **XRec reproducibility (arXiv 2510.06275, Oct 2025)**: re-runs XRec with Llama 3 as the evaluation LLM instead of GPT-3.5-turbo; open code https://github.com/julianbibo/xrec-reproducibility; finds XRec "did not consistently outperform all baseline models in every metric". — [abs](https://arxiv.org/abs/2510.06275)
- **RGCF-XRec (arXiv 2602.05544, Feb 2026)**: LLaMA 3.2-3B backbone, Amazon Sports/Toys/Beauty (642,503 interactions); no code link. — [abs](https://arxiv.org/abs/2602.05544)
- **Shielded RecRL (arXiv 2601.03608)**: PPO with KL constraint, LoRA on 0.4% of parameters, two-tower design so ranking is unchanged; Amazon Books (~50K interactions), no code link; the page reports "22.5% relative CTR improvement" and ranking "virtually unchanged" without a number. — [abs](https://arxiv.org/abs/2601.03608)
- **Simulating Users to Evaluate LLM-Generated Explanations (Electronics 2026, 15(20):4640)**: MovieLens-32M, BPR/NeuMF recommenders from RecBole, Qwen2.5 as explainer, Llama-3 as simulated respondent. [S] — [DOI](https://doi.org/10.3390/electronics15204640)
- **Decoupling information exploration and explanation (INFOCOM 2026 demo)**: lightweight graph-based recommender with controllable popularity bias, a general-purpose LLM only for post-hoc explanation; prototype on MovieLens. [S] — [DOI](https://doi.org/10.1109/infocom59046.2026.11571497)

### Inferences
- For one GPU the practical pattern is FIRE-style: scorer + SHAP/additive contributions on CPU, a 7-8B instruction model (or a 3B model as in Curr-RLCER/RGCF-XRec) at inference only, with the evidence as JSON in the prompt. This is an inference from the compute reported above, not a claim made by any single paper.
- The IntRS prompt recipe (vary what information the LLM receives: model-based / history-based / combined) is directly transferable to a smaller model, but the paper itself used a 70B model, so quality with a small model is untested.

### Gaps
- No 2025-2026 paper I verified reports a rigorous quality comparison of small (<=8B) open models for recommendation explanations with a controlled ablation; compute figures for most XRec successors are not reported.
- I did not read the GitHub repositories, so I cannot state their licences, requirements or whether they run on a single GPU.

## Key Question 2: Current best practices for evaluating explanation faithfulness without a large human study

### Takeaway
The 2025-2026 consensus is a layered, mostly automatic protocol: (i) programmatic checks that every claim appears in the supplied evidence, (ii) intervention tests (counterfactual edits of the reason or deletion/sufficiency of the cited features), (iii) a rubric-based LLM judge as a screen, validated against a small human-labelled subset. The same papers warn that LLM judges agree with humans only moderately and that neither humans nor LLMs reliably detect non-factual content.

### Cited Findings
- **Counterfactual audit of LLM-recommender reasoning (A. Shah, 2026; DOI 10.1145/3773078.3841294)**: edits the model's own reasoning trace with four operators (flip preference, swap in another user's reasoning, erase, paraphrase as control) and measures change of the top-1 item; "faithfulness gap" = mean change under flip/swap/erase minus change under paraphrase. 100 Amazon Video Games users. GPT-5 Chat gap 0.57; DeepSeek-R1 0.02; GPT-5 Reasoning -0.11; auditing DeepSeek-R1's internal trace gives 0.30. [S] (ACM DL returned 403; venue not confirmed, DOI prefix 3773078 is the same as the RecSys 2026 paper below, which suggests the same proceedings, but I did not verify that). — [DOI](https://doi.org/10.1145/3773078.3841294)
- **EviSnap (arXiv 2604.06172)**: exact additive per-concept score decomposition; faithfulness tested by deletion (removing top positive/negative concepts moves the score more than random deletion) and sufficiency (top-m concepts by |contribution| reconstruct the score). The text gives no numbers for these tests (only a figure). — [html](https://arxiv.org/html/2604.06172)
- **FIRE**: faithfulness proxied by LLM-judged "alignment" scores (user alignment Su, item alignment Si, structure adherence, unique-sentence ratio USR) plus rating-sentiment consistency; the LLM judge itself was checked by 18 annotators on 100 samples per task (mean 4.1 extraction, 4.5 alignment, 4.3 structure out of 5). Numbers: Su 0.56/0.57/0.50, Si 0.24/0.50/0.26, USR 0.99/0.91/0.95 across the three datasets. The authors list LLM-judge dependence as a limitation. — [html](https://arxiv.org/html/2508.05225)
- **Rating-explanation coherence (Curr-RLCER; Coherency Improved Explainable Recommendation, AAAI 2025, arXiv 2504.05315)**: coherence = 1 - |r1 - r2| / 4 between the model's predicted rating and a rating inferred from the explanation (GPT-3.5-turbo, a BERT sentiment classifier, plus 5 researchers on 200 samples per dataset). Curr-RLCER-3B on Baby: 0.8334 (GPT), 0.9191 (BERT), 0.8617 (human) vs best baseline PETER 0.7013 / 0.8119 / 0.7561. The paper's text claims RMSE gains (34.9/27.1/42.5%) that do not match its own Table 3 (~16.7/26.8/31.3%), which is a reason to check numbers from the PDF before citing. — [Curr-RLCER html](https://arxiv.org/html/2604.05341), [2504.05315 abs](https://arxiv.org/abs/2504.05315)
- **LLM-as-judge reliability**: Wardatzky et al. (RecSys 2026, arXiv 2609.01627): 18 explanation prototypes rated by 14 LLMs (two temperatures) vs a human user study; LLMs reach moderate rank correlation but low absolute agreement, varying with model size and construct; recommendations: concise prompts, larger judges, pre-test constructs, audit factual accuracy "as neither humans nor LLMs reliably detect non-factual content". — [abs](https://arxiv.org/abs/2609.01627)
- **Industrial judge lifecycle (Netflix, arXiv 2608.18300)**: judge built from curated human-labelled benchmarks with rationales, rubric refinement (RART), use as quality gate, and continuous human-in-the-loop drift monitoring; five-week online A/B test; no effect sizes or agreement numbers on the abstract page. — [abs](https://arxiv.org/abs/2608.18300)
- **Netflix constrained GRPO (arXiv 2609.13657)**: explanation must be faithful to elements of the shows it links and non-harmful; two LLM-judge reward models; all-three-criteria PASS rate 0.649 -> 0.956 (own judges) and 0.677 -> 0.931 (independent judge); no code. — [abs](https://arxiv.org/abs/2609.13657)
- **Catalogue hallucination measurement (arXiv 2608.10008)**: zero-shot LLM recommenders (Mistral Large, Llama-3.3-70B, GPT-OSS-120B, Claude Sonnet 4.6) emit out-of-catalogue titles at 0.6-2.7% on MovieLens-25M (11.6-38.7% Yelp, 49.3-61.0% Amazon Toys); reported rate moves by an order of magnitude with the string matcher used; matcher validated on 201 human judgments (net bias -0.040 for the adopted matcher vs +0.144 for a common fuzzy rule). [S] — [DOI](https://doi.org/10.48550/arxiv.2608.10008)
- **Robustness of explanations (RobustExplain, arXiv 2601.19120)**: five user-behaviour perturbations at several severities, multi-dimensional consistency metric (semantic, keyword, structural, length); four 7B-70B LLMs show "only moderate robustness", larger models up to 8% more stable; no code. — [abs](https://arxiv.org/abs/2601.19120)
- **Simulated-user evaluation (Electronics 2026)**: on MovieLens-32M, template-grounded explanations score feature precision 0.9996 and sufficiency 0.9999, unique-sentence ratio 0.9978; LLM-simulated users rate clarity 3.86/5 but trust only 2.60/5; replacing BPR with the more accurate NeuMF leaves survey scores practically unchanged (2000 users). Small-scale, "preliminary single-epoch checkpoints"; judged by LLMs only. [S] — [DOI](https://doi.org/10.3390/electronics15204640)
- **Preference-inconsistent explanations (PURE, arXiv 2603.03080)**: argues factual correctness is not enough (explanation may cite attributes conflicting with the user's history). **v2 (7 May 2026) is marked withdrawn by the authors** because of an issue in the evaluation protocol (P-EHR metric needs correction). Do not cite its numbers. — [abs](https://arxiv.org/abs/2603.03080)
- **Statement ranking as hallucination-free explanation (StaR, arXiv 2604.03724, Kabongo, Satouf, Guigue)**: reframes explanation as ranking review-derived statements (explanatory, atomic, unique) so standard ranking metrics apply; four Amazon Reviews 2014 categories; popularity baselines outperform SOTA on average in item-level ranking. Code/data on GitHub per a search summary (URL not seen). [A via SciSpace/web summary; arXiv abs not fetched] — [PDF](https://arxiv.org/pdf/2604.03724)
- **General (non-recommender) faithfulness tests**: Faithfulness Serum (ACL 2026 long paper, arXiv 2604.14325): counterfactual tests show LLM textual explanations often unfaithful; training-free attention-level intervention guided by token-level attribution heatmaps; benchmarks MMLU, CommonsenseQA, SciQ, ARC, OpenBookQA. CHIVE (arXiv 2608.16747): evaluates explanations by whether they predict model behaviour on counterfactual edits; reports no uplift from the interpretability techniques studied. — [2604.14325](https://arxiv.org/abs/2604.14325), [2608.16747](https://arxiv.org/abs/2608.16747)
- **Fuzzy+LLM medical studies (Perez-Ferreiro et al.)** measure faithfulness as hallucination counts with Wilcoxon signed-rank tests (p < 0.001) (FUZZ-IEEE 2025, DOI 10.1109/FUZZ62266.2025.11152139) and in the IJAR 2026 follow-up (DOI 10.1016/j.ijar.2026.109828) find that adding counterfactuals neither raises hallucination nor lowers accuracy, whereas Chain-of-Thought prompting increases verbosity and hurts readability with no apparent benefit. [S for both] — [FUZZ-IEEE record](https://citius.gal/en/research/publications/generating-trustworthy-explanations-with-a-language-model-enriched-by-fuzzy-rule-based-systems/), [IJAR DOI](https://doi.org/10.1016/j.ijar.2026.109828)
- **User-study evidence for what users value**: Feng, Feuerriegel, Shrestha (arXiv 2501.12152, ICWSM 2026): pre-registered N=759 experiment + 30 interviews on LLM movie explanations; contextualised (past-behaviour-aware) explanations better meet cognitive needs and raise intention to watch, little benefit for utilitarian/affective needs, and can "feel excessive if overused". Manderlier et al. (arXiv 2509.18980, IntRS @ RecSys 2025): N=326, MovieLens-32M subset, significant but negligible-to-small effects on transparency/effectiveness/satisfaction, no significant effect on persuasion or trust; users found explanations repetitive/generic; their own history-based explanation was not faithful to how the recommender computes scores. — [2501.12152](https://arxiv.org/abs/2501.12152), [2509.18980](https://arxiv.org/abs/2509.18980)
- **Known risks of LLM components in recommenders**: feedback-loop study (arXiv 2602.07442) reports LLM components can amplify popularity bias and inject spurious signals via hallucination [S]; BiasRecBench (arXiv 2603.17417) shows LLM-as-recommender agents succumb to injected biases [S]; position bias in LLM recommendation (arXiv 2508.02020, RISE prompting) [S]; uncertainty/fairness benchmark on movies and music (arXiv 2602.02582; Gemini 1.5 Flash SNSR 0.1363, SNSV 0.0507) [S]. — [2602.07442](https://doi.org/10.48550/arxiv.2602.07442), [2603.17417](https://doi.org/10.48550/arxiv.2603.17417), [2508.02020](https://doi.org/10.48550/arxiv.2508.02020), [2602.02582](https://doi.org/10.48550/arxiv.2602.02582)

### Inferences
- A low-cost faithfulness protocol assembled from these papers: (1) claim-level fact check against the exact JSON fed to the LLM (TMDB fields, genre, year, cast) with a validated title/entity matcher; (2) a deletion/sufficiency test on the features the explanation cites (remove the cited feature from the scorer input and check the score drop, compare with random removal); (3) an optional counterfactual edit of the cited reason (flip/erase/paraphrase control, as in Shah) if the explanation is produced by a reasoning LLM; (4) an LLM judge with a rubric as a screen only, checked on a small human-labelled subset (FIRE used 100 items per task; Curr-RLCER 200 per dataset with 5 raters).
- Because template explanations get near-perfect automatic faithfulness yet low simulated trust (Electronics 2026), automatic faithfulness alone should not be presented as explanation quality; report it next to a readability/usefulness measure.
- Programmatic checks matter because neither LLM judges nor humans reliably detect non-factual content (Wardatzky et al.).

### Gaps
- I could not open the full text of Shah's counterfactual audit (ACM DL 403, no arXiv version found), so its venue, code and operator details are unverified.
- No paper I verified supplies a validated, off-the-shelf faithfulness metric for recommendation explanations that is accepted across studies; FIRE itself states that each study picks its own metrics.
- Inter-judge agreement numbers (e.g. Pearson/Spearman) for LLM judges on recommendation explanations are not in the abstracts I read; Wardatzky et al. and Doh et al. (arXiv 2607.25640, music CRS, n=400 ratings from 20 experts, "moderate positive alignment") would need full-text reading.

## Key Question 3: Does any 2025-2026 work tie explanations to the actual features that drove the model score?

### Takeaway
Yes, a small set of papers does, in three flavours: SHAP attributions verbalised by an LLM (FIRE), score decompositions that are exact by construction (EviSnap), and ranking-signal factors converted to tags in the prompt (FAB-LPR, snippet only). A fourth line (Shah's counterfactual audit) shows the opposite risk: the displayed reasoning of some LLM recommenders barely drives the output. None of the grounded approaches has released code that I could find, and none explains a movie Top-10 on MovieLens + TMDB text.

### Cited Findings
- **FIRE**: SHAP on the sentiment predictor, top-K features to prompt; claims explanations "grounded in the actual decision-making process of the model"; best weighted F1 on Yelp and Amazon, competitive on TripAdvisor; baselines PETER, PEPLER (MF, MLP), PRAG, ERRA, CIER; limitation: explanations sometimes omit item features, omit user needs, or fail to connect the two; the predictor is a 3-class sentiment classifier rather than a Top-K ranker. — [html](https://arxiv.org/html/2508.05225)
- **EviSnap (arXiv 2604.06172; 8 pages; page lists submitted 9 Jan 2026 though id suggests April 2026)**: LLM offline distils reviews into facet cards with verbatim supporting sentences; clustering gives a domain-agnostic concept bank; one linear concept-to-concept map transfers users across domains; a linear head gives per-concept additive contributions, enabling exact decomposition and "what-if" edits. Amazon Reviews 2014, six transfers among Books/Movies/Music; baselines EMCDR, PTUPCDR, MACDR, DeepCoNN+, HeroGraph. Averaged vs DeepCoNN+: MAE 0.845 -> 0.818 (3.3%), RMSE 1.085 -> 1.055 (2.7%); vs MACDR: 6.6% lower MAE, 6.4% lower RMSE; best on 5/6 transfers (HeroGraph wins Music->Movies). No LLM calls at train or inference time after the offline stage. Limitations: depends on the offline LLM/prompts, needs enough review text, linear form may miss interactions. Code: none found. — [html](https://arxiv.org/html/2604.06172), [abs](https://arxiv.org/abs/2604.06172)
- **FAB-LPR (ECTI-CON 2026)**: decomposes a bias-aware link-analysis POI ranker's internal signals into interpretable factors, converts them to semantic tags in prompt templates; reports "17% improvement" in explanation faithfulness over baseline on one real-world dataset (POI domain). [S] — [DOI](https://doi.org/10.1109/ecti-con68836.2026.11608417)
- **CauSAL-Rec (ICICC 2026)**: structural causal model; LLM explanations must cite valid causal-parent evidence; "Faithfulness Verifier" checks consistency against the causal graph; NDCG@10 +10.0 / +9.3 / +10.2% over LLM4Rec on three datasets. [S] — [DOI](https://doi.org/10.1109/icicc71012.2026.11637910)
- **APLE (UMAP/ACM, May 2026)**: argues LIME/SHAP/IG are too slow for live recsys and association-based, and that LLM verbalisation adds hallucination, leakage and latency risks; proposes a framework targeting faithfulness, personalisation, low latency, adaptability. [S] — [DOI](https://doi.org/10.1145/3795766.3799741)
- **Rule/fuzzy + LLM**: Perez-Ferreiro, Catala, Bugarin-Diz, Alonso-Moral, FUZZ-IEEE 2025: fuzzy rule-based system supplies factual content to a template-based explainer, LLM verbalises; open-source modular architecture claimed, no repository link found; medical (heart disease) validation; significant reduction in hallucinations (Wilcoxon p < 0.001) and more compact narratives without accuracy loss. IJAR 2026 (4 authors, same group): factual + counterfactual fuzzy explanations, CoT prompting did not help. Both [S] and both medical, not recommendation. Oettgen's Fuzzy-LLM preprints (Zenodo, Oct 2025, sensory/culture-medium data, metrics CFI/Align-Score/Bias Rate) are non-peer-reviewed repository records [S]. I found **no 2025-2026 recommender paper that combines fuzzy/linguistic rules with an LLM verbaliser.** — [FUZZ-IEEE](https://citius.gal/en/research/publications/generating-trustworthy-explanations-with-a-language-model-enriched-by-fuzzy-rule-based-systems/), [IJAR](https://doi.org/10.1016/j.ijar.2026.109828), [Zenodo 17386633](https://doi.org/10.5281/zenodo.17386633)
- **Counterfactual evidence of non-faithful reasoning**: Shah (2026): DeepSeek-R1 and GPT-5 Reasoning show little reason-responsiveness in the displayed explanation (gaps 0.02 and -0.11) while GPT-5 Chat shows 0.57. [S] — [DOI](https://doi.org/10.1145/3773078.3841294)
- **ExplainRec (arXiv 2511.14770)** claims "preference attribution tuning" on MovieLens-25M and Amazon with +0.7% AUC (movies) and +0.9% (cross-domain); abstract only, no code; the same author group (Ma Bo, Liu Luyao, Lau Simon and others) posted two other broad-scope framework papers in the same weeks (arXiv 2510.01606, 2510.01622). I could not verify any of them beyond the abstracts. [S] — [abs](https://arxiv.org/abs/2511.14770)

### Inferences
- For a MovieLens + TMDB project the closest verified recipe is FIRE-style attribution (or an additive scorer à la EviSnap), then a constrained verbalisation prompt, then deletion/sufficiency checks. The movie-domain gap: FIRE's Amazon movies-TV data is sentiment classification, EviSnap's movies are Amazon reviews, and the IntRS study is the only MovieLens one (but not attribution-based).
- A fuzzy design (membership degrees and rule firing strengths as the "evidence", LLM only rewrites) matches the structure of the FUZZ-IEEE 2025 architecture, with the caveat that its evidence is medical and its code location is unconfirmed. This is my reading, not a claim of those papers.

### Gaps
- No verified code for FIRE, EviSnap, FAB-LPR, CauSAL-Rec or the fuzzy-LLM architecture.
- No 2025-2026 paper found that applies SHAP/rule attribution to a Top-K ranker on MovieLens with an LLM verbaliser and reports faithfulness tests.
- FAB-LPR, CauSAL-Rec, APLE and the Shah audit are [S]: their faithfulness metrics and datasets were not read.

## Usefulness ranking for the practice project (MovieLens + TMDB text, HF models, one GPU, Top-10 with a reason per item)
Inferences from the verified material above, in descending order of usefulness:
1. FIRE (2508.05225): attribution -> structured prompt -> LLM; swap gpt-4.1-mini for a local 7-8B instruct model. Evidence: SHAP on a tabular scorer, alignment metrics with a validated judge. No code.
2. EviSnap (2604.06172): shows exact additive decomposition and deletion/sufficiency tests; needs review text, which MovieLens lacks but TMDB overview/keywords/reviews could partly substitute (that substitution is my suggestion).
3. IntRS 2025 study (2509.18980) with open code: prompt design and user-study protocol on MovieLens 32M; replace the 70B model with a small one.
4. Counterfactual audit (Shah) and Wardatzky et al. for the evaluation chapter; Ravikumar's matcher validation for title hallucination.
5. FUZZ-IEEE 2025 / IJAR 2026 for the fuzzy-to-text architecture (code location unconfirmed).
6. Curr-RLCER for the rating-explanation coherence metric (training is too heavy for one GPU).

## Tool notes
- **SciSpace search-papers** (natural-language questions) was the best discovery tool: returns title, authors, date, DOI, full abstract and often a PDF link in one call; several queries surfaced 2026 items (RecSys 2026, IJCAI-26, ACL 2026) that general web search missed. Limits: no code links, no venue for many arXiv items, dates sometimes differ from arXiv v1 dates (e.g. Coherency Improved: SciSpace 9 Apr 2025 vs arXiv page 21 Feb 2025; ExplainRec: SciSpace 3 Oct 2025 vs arXiv id 2511), and IEEE/ACM entries have abstracts only.
- **WebSearch (standard mode)** returns a summarised answer with links; useful for leads (RGCF-XRec, HyperXRec, Shielded RecRL, Curr-RLCER, StaR) but the summaries can be wrong, so every arXiv item was re-checked on its abstract page.
- **WebFetch on arxiv.org/abs** works and was reliable for title, authors, dates, comments, code links. **arxiv.org/html** gave full-text details (datasets, compute, limitations) for FIRE, EviSnap, Curr-RLCER and 2509.18980, but the pages are processed by a small summariser and truncated at ~100k characters, so quoted numbers should be re-checked against the PDF. The fetch summariser also reported odd submission dates for Shielded RecRL (14 Oct 2025 for id 2601.03608) and EviSnap (9 Jan 2026 for id 2604.06172) that I could not reconcile; I report both.
- **Blocked or unusable**: dl.acm.org returned HTTP 403 (so the Shah counterfactual-audit and RecSys 2026 DOI pages could not be read; the RecSys paper was verified through its arXiv twin 2609.01627); doi.org redirects need a second fetch; two PDFs (CEUR AXAI paper11, a SBC Portuguese-language paper on axiomatic faithfulness of movie explanations) came back as binary and could not be parsed because pdftoppm is not installed, so they are not catalogued. The CEUR paper's authors appear to be Maes, Michiels, Smets (VUB), a workshop position paper on factuality and faithfulness of LLM explanations in recommenders, but I could not read its title or text. IJCAI-26 HyperXRec was not fetched directly.
- Total tool budget exceeded the suggested 15 calls because the topic had several sub-areas; no search of GitHub repositories was done.
