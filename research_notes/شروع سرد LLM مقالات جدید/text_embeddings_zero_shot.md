## Q1. Do text embedding models beat LLM rerankers for cold start in 2025-2026, and when does the LLM win?

### Takeaway
Three independent 2025-2026 studies agree that a plain text-embedding (TEM) retriever is a stronger and far cheaper training-free cold-start baseline than a zero-shot LLM reranker; the LLM only wins in narrow cases (very short user text on MovieLens-1M, some individual users, or when a candidate pool is already good). Two of the three studies identify the candidate-generation/retrieval stage, not the reranker, as the bottleneck.

### Cited Findings

**Anchor paper (verified)**
- **Are Large Language Models Really Effective for Training-Free Cold-Start Recommendation?** Genki Kusano, Kenya Abe, Kunihiro Takeoka (NEC). arXiv 2512.13001, v1 15 Dec 2025, cs.IR, no venue listed. URL https://arxiv.org/abs/2512.13001 . **[ABS + HTML]** Code: none found on the page.
  - Task: training-free cold start. "Narrow" CS = user has no interactions (profile text only); "broad" CS = m history items (main m=1; also 3, 5, 10); cross-domain variant also tested.
  - Datasets: MovieLens-1M (user age/gender/occupation turned into text), a Kaggle job-recommendation dataset (2012, split into Job-exp / Job-no-exp), Amazon Reviews (Music, Movie, Book). No version numbers for Amazon given.
  - Text embedding models: multilingual-e5-large, bge-m3, gte-modernbert-base, gte-Qwen2-1.5B-instruct, gte-Qwen2-7B-instruct, Qwen3-Embedding-0.6B, Qwen3-Embedding-8B.
  - LLM rerankers: gpt-4.1, gpt-4.1-mini, Qwen3-8B (zero-shot, pick and order top-10 of 50, candidate order randomised).
  - Baseline: BM25 only. Metrics: Recall@10, nDCG@10; one-sided Wilcoxon signed-rank vs BM25 (p=1e-4). Protocol: 500 users per dataset, last 3 interactions = positives, candidate set = 3 positives + 47 random unseen in-domain items.
  - Headline numbers (all datasets pooled, Recall@10 / nDCG@10): narrow CS: BM25 0.315/0.362; Qwen3-Embedding-8B 0.392/0.430; gte-Qwen2-7B 0.372/0.412; gpt-4.1 0.311/0.283; gpt-4.1-mini 0.282/0.260; Qwen3-8B 0.114/0.101. Broad CS (m=1): BM25 0.397/0.477; Qwen3-Embedding-8B 0.514/0.569; gte-Qwen2-7B 0.536/0.581; gpt-4.1 0.433/0.377. Cross-domain (m'=1): BM25 0.215/0.259; Qwen3-Embedding-8B 0.347/0.383; gpt-4.1 0.244/0.224.
  - Where the LLM wins: narrow CS on MovieLens-1M, gpt-4.1 Recall 0.269 vs BM25 0.202 (significant) although nDCG 0.247 vs 0.235 not significant; gpt-4.1 has higher Recall than BM25 in broad CS but lower nDCG; with only 10 candidates at m=0 the Recall gap to Qwen embeddings was no longer significant; in error analysis the LLM beat the TEM for fewer than 25% of users in every dataset except MovieLens narrow CS. LLM query expansion helped weak embedders, not strong ones (hybrid did not reliably help at m>=1).
  - Limitations: only 500 users/dataset; random negatives (easy candidate set); MovieLens narrow-CS scores low; long Job texts may hurt LLM; compute/GPU not reported; Qwen3-8B reranker result is extremely low (0.114) and the paper does not explain why in the parts I could read.
  - Usefulness: **HIGH** (direct template for the thesis: BM25 + Qwen3-Embedding / bge / e5 vs LLM reranker; same ML-1M).

**Corroborating 2026 studies**
- **Diagnosing LLM-based Rerankers in Cold-Start Recommender Systems: Coverage, Exposure and Practical Mitigations.** Ekaterina Lemdiasova, Nikita Zmanovskii. arXiv 2604.16318 (fetched page states v1 "09 Feb 2026"; the 2604 id would normally mean April 2026, so the date is inconsistent, verify on arXiv before citing). https://arxiv.org/abs/2604.16318 . **[HTML]** Code: https://github.com/nikita-zmanovskiy/cold-start-algorithm
  - IMPORTANT caveat: the "LLM-based reranker" here is a **cross-encoder (cross-encoder/ms-marco-MiniLM-L-6-v2, 22M or 66M params, the paper gives both)**, not a generative LLM. Embedding model: all-MiniLM-L6-v2 (22M) with FAISS Flat.
  - Data: Serendipity-2018 (49,157 movies, 104,661 users), not a named MovieLens version; 500 cold-start users, 3 seeds; item text = title + genres + top-10 tags. Baselines: Random, Popularity, Embedding Cosine, Candidates Only. Metrics HR@10, nDCG@10, Recall@50/200/1000, Gini.
  - Numbers: Popularity HR@10 0.268; Embedding Cosine 0.101; Random 0.023; Candidates-only 0.011; cross-encoder reranker 0.008 (a 33.5x gap vs popularity). Recall@200 of FAISS candidates only 0.109 vs 0.609 for baselines; reranker top-1 concentrates on 3 unique items across 500 users (Gini 0.480). Hybrid ANN+BM25 retrieval raised Recall@200 0.109 to 0.234 (preliminary). CPU only (Xeon E5-2650 v4); 7.23 s/user at pool 1000.
  - Limitations: single domain, 500 users, ensemble weights (0.3/0.5/0.2) not validated, no GPU runs. Usefulness: **MED** (shows popularity and embedding-cosine baselines are hard to beat; but not a real generative LLM).
- **Diagnosing and Mitigating Retrieval Bottlenecks in LLM-Based Cold-Start Recommendation.** Zhe Dong, Fang Qin, Manish Shah, Yicheng Wang. arXiv 2606.29947, v1 29 Jun 2026, cs.IR. https://arxiv.org/abs/2606.29947 . **[HTML]** Code https://github.com/dongzhe1/rec-diag-bench/tree/0.0.0 (Zenodo 10.5281/zenodo.20993306), data Zenodo 10.5281/zenodo.20991039.
  - Datasets: Amazon Reviews 2023 (Arts, Video Games), MIND small, **MovieLens-20M**, Yelp Philadelphia. Chronological 70/10/20 split, buckets item-new / item-cold / long-tail / user-cold / warm.
  - Models: Qwen3-8B (bf16, primary), Qwen3-32B (scale check), Llama-3.3-70B-Instruct (4-bit). Retrievers: SBERT, BGE dense retrieval, a frozen two-tower retriever. Baselines: popularity, item-kNN, TF-IDF, Markov, BPR, LightGCN, SASRec, cross-encoder, RRF fusion, CARA.
  - Findings: in positive-controlled pools (gold item injected) Qwen3-8B wins no domain; 32B narrows but rarely closes the gap. Standard single retrievers put the gold item in the top-200 only 4.6-22.9% of the time. End-to-end Recall@10 with LLM reranking <= 1.4% in all domains. A learned hybrid fusion (LHF, gradient-boosted over ten retrievers' pools) recovers 5-61% of oracle headroom depending on domain; the LLM reranker often degrades the LHF pool. Prompt-level graph evidence rarely helps (gains come from a tail prior).
  - Compute: single H100-class GPU; Qwen3-8B 58.7 pairs/s and 36 GB peak GPU memory vs LightGCN 55,455 pairs/s and 4.2 GB (about 1000x slower, 9x more memory).
  - Limitations (authors): LLM reranking evaluated on sampled subsets; prompts not exhaustively searched; offline only. Note: a search-engine summary of this paper said rerankers show "genuine semantic cold-start ability in controlled pools, especially on news"; the page text I read says Qwen3-8B "wins no domain" in controlled pools. These two readings differ in wording and I did not reconcile them; read the paper's controlled-pool table before citing either.
  - Usefulness: **HIGH** for protocol ideas (bucketing by item age, coverage@200 diagnostic, pool-quality vs reranker split) and for the claim that retrieval, not reranking, limits cold start. Qwen3-8B at 36 GB does not fit a Colab T4 in bf16.

**Related hybrid / training-free methods**
- **Training-Free LLM-Based Recommendation with Post-LLM Item Refinement Using Collaborative Signals (CoRRe).** Kyungho Kim, Sunwoo Kim, Geon Lee, Shinhwan Kang, Sojeong Kim, Liam Collins, Bhuvesh Kumar, Donald Loveland, Kijung Shin. arXiv 2608.19665, v1 20 Aug 2026; CIKM 2026 short paper. https://arxiv.org/abs/2608.19665 . **[ABS]** Injects item-item co-purchase-graph direction and popularity-based magnitude into LLM-generated item embeddings, matched to LLM-generated user interests; claims to beat training-free baselines and be competitive with trained ones. Datasets, models, numbers, code not visible on the abstract page. Usefulness: LOW-MED.

Usefulness: MED-HIGH (MovieLens cold-start with frozen-LLM text embeddings; verify).
- **Enhancing Collaborative Filtering With Large Language Model Embeddings for User Cold-Start Recommendation (LLM-CF).** Eranki R. N. Rao, N. S. Koundinya, S. D. Veeramachaneni, A. K. Pujari. IEEE PRML 2026 (doi 10.1109/prml71097.2026.11687003). **[SNIP]** Frozen sentence-encoder embeddings + MLP projection + warmth-aware gate over a BPR-MF backbone; MovieLens-1M and Amazon Office Products; user cold-start NDCG@10 3.4x and 2.0x vs BPR-MF; authors say specialised methods can beat it on extreme-sparsity item cold start. Usefulness: HIGH (almost exactly a "text embedding + CF hybrid" recipe), but low-tier venue and unverified.

Usefulness: MED.
- **ProbLLM / Turning Cold Entities Warm: LLM-Based User and Item Interaction Simulation.** Hao Chen et al. ACM (doi 10.1145/3848638), 30 Sep 2026. **[SNIP]** LLM retrieves candidate pool then scores pairs with probability-form prompt; pseudo-interactions train a CF backbone. Usefulness: LOW-MED.

Usefulness: LOW (survey useful only for related-work citation).

### Inferences
- For the thesis, "TEM kNN / BM25 / popularity" must be the first three baselines before any LLM reranker; every study here finds at least one of them very hard to beat in cold start.
- The LLM reranker's disadvantage in 2512.13001 may partly come from easy random-negative candidate sets plus short text; with realistic candidate sets the problem shifts to retrieval coverage (2606.29947). This is my reading, not a claim of the papers.
- Ranking quality of Qwen3-8B as a reranker in 2512.13001 (Recall 0.114) is so low that prompt/format/parsing issues are a plausible confound; the paper does not discuss it in what I read.

### Gaps
- No study found that compares text embedders against an open LLM reranker on MovieLens plus TMDB overview text at one-GPU scale with fine-tuned (not zero-shot) embedders.
- 2512.13001 code and compute not reported; HTML read through a summariser only.
- Date inconsistency for 2604.16318 unresolved. Reconciliation of the 2606.29947 "LLM wins in controlled pools" wording unresolved.
- No LightFM comparison found in any paper.

## Q2. Zero-shot / in-context LLM rankers: best open models and strategies, and size of position / popularity / history-order biases

### Takeaway
Position bias in listwise LLM reranking is large and persistent (rank correlation between original and reversed candidate lists as low as 0.47 for LLaMA-3.3-70B at 30 candidates; an attacker can push targets into top-5 for up to 57% of cases using 50 reorderings). Prompt-only fixes (shuffling and aggregating, iterative selection, "ignore position" instructions) help only partly; architectural or training-time fixes (permutation-invariant attention masks, consistency regularisation) give near-perfect invariance at a small accuracy cost. I found no 2025-2026 paper that systematically ranks open HuggingFace models for zero-shot movie ranking.

### Cited Findings

**Position bias, quantification and fixes**
- **Evaluating Position Bias in Large Language Model Recommendations (RISE).** Ethan Bito, Yongli Ren, Estrid He (RMIT). arXiv 2508.02020, v1 4 Aug 2025, cs.IR. https://arxiv.org/abs/2508.02020 . **[ABS + HTML]** No code link on the page.
  - Model: LLaMA 3.3 70B only. Datasets: MovieLens-1M, Amazon Books. Candidate list K in {10,20,30}. Metrics: Positional Consistency (Kendall tau between original and reversed list), output similarity across shuffles, input sensitivity, Recall@5, NDCG@5.
  - Standard prompting PC: MovieLens 0.67 (K=10) falling to 0.47 (K=30); Amazon Books 0.55 to 0.47 (the text cites 0.55-0.57, which conflicts with Table 1's 0.47; paper-internal inconsistency).
  - RISE (Ranking via Iterative SElection) @1: MovieLens PC 0.75 (K=10), 0.69 (K=30); Amazon Books 0.65 at both; claims up to 25% bias reduction. Bootstrapping baseline uses T=9 shuffles with Borda count. Standard prompting and bootstrapping sometimes score higher Recall@5/NDCG@5 than RISE, especially on Amazon Books. Larger N in RISE@N lowers PC and accuracy.
  - Limitations: single (70B) model; popularity effects described as modest; not runnable on one modest GPU. Usefulness: MED (bias metrics PC/Sim are easy to copy; the 70B model is not).
- **One Pass, Any Order: Position-Invariant Listwise Reranking for LLM-Based Recommendation (InvariRank).** Bito, Ren, He. arXiv 2604.27599, v1 30 Apr 2026; SIGIR 2026 (pp. 3625-3629). https://arxiv.org/abs/2604.27599 . **[ABS + HTML]** Code https://github.com/ejbito/InvariRank
  - Backbones: LLaMA-3.2-3B-Instruct, Mistral-7B-Instruct, **LoRA rank 16, alpha 32**, 500 optimizer steps, effective batch 16, lr 5e-5, AdamW, 5% warmup, max length 4096, history truncated to 20. Datasets: MovieLens-32M, Amazon Books (chronological 70/10/20); candidates K=25 from a LightGCN retriever.
  - Baselines: zero-shot prompting, bootstrapping (permutation aggregation), SGS, STELLA (post-hoc calibration), LFT (listwise fine-tuning without the architecture constraints). Metrics: HR@5/10, nDCG@5/10; Kendall tau, Spearman rho, top-5 agreement.
  - ML-32M, LLaMA-3B: InvariRank tau 0.9883, rho 0.9984, T@5 0.9906 vs LFT tau 0.8861; nDCG@10 0.8166 vs 0.8486 (LFT slightly better). Mistral-7B: tau 0.9936 vs 0.8769; nDCG@10 0.8523 vs 0.8698. Books LLaMA-3B: tau 0.9834 vs 0.7758; nDCG@10 0.3871 vs 0.4108.
  - Limitations: candidate isolation drops cross-candidate comparison; fixed-size lists; two datasets; GPU/compute not reported in what I read. Usefulness: **HIGH** (LoRA on 3B model, MovieLens candidate reranking with LightGCN retriever; a 3B + LoRA run fits a free GPU in principle, memory not reported).
- **Position Bias Undermines Preference Consistency in Listwise LLM-Based Reranking.** Bito, Ren, He. arXiv 2608.03091, v1 4 Aug 2026; accepted RecSys 2026. https://arxiv.org/abs/2608.03091 . **[ABS]** Introduces pairwise preference instability, global preference inconsistency, listwise output consistency; finds they diverge from accuracy and from marginal position-exposure skew, so flattening exposure across positions is not enough. Models/datasets not named on the abstract page. Code https://github.com/ejbito/InvariRank . Usefulness: MED (metrics).
- **Ranked by Position: Order Sensitivity as an Exploitable Attack Surface in LLM Listwise Recommenders.** Ge Zhang, Jingru Cheng, Huiyuan Chen. arXiv 2607.24869, v1 26 Jul 2026. https://arxiv.org/abs/2607.24869 . **[ABS]** promo@k metric; MovieLens, Amazon Books, Amazon Fashion; promo@5 up to 0.57 at 50 orderings; permutation stability predicts vulnerability; a bidirectional T5 encoder scorer, permutation-consistency regularisation and architectural invariance mitigate it; pointwise scoring avoids the bias but lowers ranking quality. Code https://github.com/geoz-lab/position_bias_attack . LLM names not on the abstract page. Usefulness: MED (supports using pointwise or encoder scoring).
- **Prompt-Based LLMs for Position Bias-Aware Reranking in Personalized Recommendations.** Md Aminul Islam, Ahmed Sayeed Faruk. arXiv 2505.04948 (May 2025). **[SNIP, listing reported WITHDRAWN]** GPT-4o reranks LightGCN top-k on MovieLens-100K; shuffling history improved ranking quality but LLM reranking did not beat the base model; "ignore position" instructions did not help. Do not cite as established; withdrawn status came from a search summary, confirm at https://arxiv.org/abs/2505.04948 . Usefulness: LOW (withdrawn).
- **Adaptive Repetition for Mitigating Position Bias in LLM-Based Ranking.** Vardasbi, Penha, Hauff, Bouchard. arXiv 2507.17788, 25 Jul 2025. **[SNIP]** General (not recommender-specific) re-ranking and alignment tasks, three LLMs; dynamic early-stopping of repeated shuffled calls cuts LLM calls by 81% on average (87% with confidence variant) at similar accuracy. Usefulness: MED (cheap bootstrapping).
- **LLM-based Listwise Reranking under the Effect of Positional Bias (DebiasFirst).** Qiao, Huang, Ma, Wang, Yin, Kanoulas, Yates. arXiv 2604.03642, 4 Apr 2026. **[SNIP]** Passage reranking, inverse-propensity position calibration plus position-aware augmentation during fine-tuning. Usefulness: LOW (not recsys).
- **Reasoning to Rank: An End-to-End Solution for Exploiting LLMs for Recommendation.** Kehan Zheng, Deyao Hong, Qian Li, Jun Zhang, Huan Yu, Jie Jiang, Hongning Wang. arXiv 2602.12530, v1 13 Feb 2026. https://arxiv.org/abs/2602.12530 . **[ABS]** RL-trained user-item-level reasoning to avoid position bias; three Amazon datasets plus an industrial set; models and code not on the page. Usefulness: LOW (RL, heavy).

**History-order sensitivity**
- **Lost in Sequence: Do Large Language Models Understand Sequential Recommendation?** Sein Kim, Hongseok Kang, Kibum Kim, Jiwan Kim, Donghyun Kim, Minchul Yang, Kwangjin Oh, Julian McAuley, Chanyoung Park. arXiv 2502.13909, v1 19 Feb 2025; KDD 2025 research track. https://arxiv.org/abs/2502.13909 . **[ABS]** LLM4Rec models often ignore interaction order in training and inference; proposes LLM-SRec (distils a pretrained sequential recommender's user representation into an LLM via light MLPs, no LLM fine-tuning). Code https://github.com/Sein-Kim/LLM-SRec . A search summary says it uses Llama-3.2-3B-Instruct (and 3.1-8B as a larger check) **[SNIP detail]**. Usefulness: MED-HIGH.
- **Enhancing Temporal Sensitivity of LLM for Recommendation with Counterfactual Tuning (CETRec).** arXiv 2507.03047 **[SNIP]**: LLM recommenders show only small performance drops under order perturbation; proposes causal tuning. Usefulness: LOW-MED.

**Popularity bias and memorisation**
- **Bridging Semantic Understanding and Popularity Bias with LLMs (FairLRM).** Renqiang Luo, Dong Zhang, Yupeng Gao, Wen Shi, Mingliang Hou, Jiaying Liu, Zhe Wang, Shuo Yu. arXiv 2601.09478 (page shows v3, 18 Jan 2026; v1 date not stated; formatted for The Web Conference 2026). https://arxiv.org/abs/2601.09478 . **[HTML]** Code https://github.com/LuoRenqiang/FairLRM
  - Models: Qwen-max (API), a local Llama (the text says "Llama-77B", likely a typo, size unverified). Datasets: MovieLens-20M and Goodbooks-10k (the paper's Goodbooks counts are internally inconsistent). Prompt-only method: split bias into item side (long-tail coverage, LtC) and user side (mean rank miscalibration, MRMC); label users popularity-biased vs niche-biased and encode the rule in the prompt. Baselines: vanilla prompt, Pop.Debiasing, diversity prompts.
  - MovieLens, Qwen-max vanilla to FairLRM: LtC 0.013 to 0.062, MRMC 0.586 to 0.302, MRR@10 0.078 to 0.452, F1@10 0.576 to 0.810. MovieLens Llama: LtC 0.036 to 0.048, MRMC 0.370 to 0.331. The authors argue "diversity" prompts mostly return more popular items.
  - Limitations: two LLMs/datasets; threshold must be tuned per LLM; no limitations section. The size of the MRR jump (0.078 to 0.452) is large enough to deserve a sanity check against the code. Usefulness: MED (prompt-only popularity-bias fix on MovieLens, but 20M vs the user's ML version unknown).
- **Do LLMs Memorize Recommendation Datasets? A Preliminary Study on MovieLens-1M.** Dario Di Palma, Felice Antonio Merra, Maurizio Sfilio, Vito Walter Anelli, Fedelucio Narducci, Tommaso Di Noia. arXiv 2505.10212, v1 15 May 2025 (SIGIR 2025 short, doi 10.1145/3726302.3730178 listed as related DOI; venue not stated on the page). https://arxiv.org/abs/2505.10212 . **[ABS]** All tested GPT and Llama families show some MovieLens-1M memorisation; recommendation performance correlates with memorisation; memorisation is popularity-biased. Code https://github.com/sisinflab/LLM-MemoryInspector . Usefulness: **HIGH** (a contamination warning for zero-shot LLM results on MovieLens; consider reporting results on items released after model cut-offs or on TMDB-only text).
- **The Mental World of LLMs in Recommendation (LRWorld).** Guangneng Hu. arXiv 2512.17389, v1 19 Dec 2025. https://arxiv.org/abs/2512.17389 . **[ABS]** Benchmark of 38K+ samples, 31 tasks; "dozens of LLMs" (unnamed on page); no single model best across factors; LLMs weak at deep personalised embeddings, good at shallow item-item similarity; ablates model size and position bias. Usefulness: LOW-MED.
- **From Bias to Fairness: Mitigating Popularity Bias in LLM-Based Recommendation via SFT and DPO.** Rithwik Chitla, Ishaan Mali, Benescia Kashyap, Raphael Fohine. Zenodo records (doi 10.5281/zenodo.22358051, 4 Sep 2026; 10.5281/zenodo.22726663, 12 Sep 2026), not peer reviewed and not arXiv. **[SNIP]** Qwen2.5 1.5B and 3B on MovieLens-100K; zero-shot/few-shot skewed; popularity-capped SFT sampling (73.9% tail items); SFT + DPO on 3B gives 59.2% lower ARP and TailCov 95.45% vs 37.21% zero-shot. Usefulness: MED (small Qwen + ML, but unreviewed and tiny dataset).
- Low-confidence items, **[SNIP]** only: *MASRank* (Bo Ma et al., IEEE ICHCI 2025, doi 10.1109/ichci67614.2025.11291733; five-agent LLM ranker, claims +0.8% NDCG@10 on ML-25M/Amazon/Yelp); *SPLICE: When a Weaker LLM Ranker Helps a Strong Sequential Recommender* (Bo-Chian Chen, Zenodo 10.5281/zenodo.23321451, 12 Oct 2026, single author; frozen sequential retriever + open-weight LLM single-pass probabilities over top-50, +12.1% NDCG@10 on Beauty, +13.1% Toys, MovieLens-1M also improved; model names obscured); *GraphRAG-IRL* (arXiv 2604.19128, Apr 2026; IRL + persona-guided LLM re-ranking, ML-1M NDCG@10 up to +16.8% over IRL-only); *LLMs in the Loop: From Ratings to Ranked Recommendations* (Low and Ng, FAIA 2026, doi 10.3233/faia260019; Llama 3.1 70B, Qwen 2.5 32B, Mistral 7B, OpenLLaMA 13B; UBCF beat LLMs at rating prediction while LLMs did well at ranked lists). I would not cite these without opening them.

**Strategies that recur (from the above)**
- Shuffle-and-aggregate (bootstrapping, T=9 with Borda count) is the standard prompt-level fix (2508.02020 baselines; background in LLMRank 2023); iterative-selection (RISE) improves consistency but can reduce accuracy; "ignore position" instructions reportedly do nothing (withdrawn 2505.04948, treat as weak evidence); pointwise scoring avoids order bias but ranks worse (2607.24869); architectural invariance via attention mask plus shared RoPE positions gives tau around 0.98-0.99 (2604.27599).

### Inferences
- A cheap, defensible protocol for the thesis: pointwise (or logit-scored) LLM relevance with a 1-4B open model, plus T shuffled listwise runs aggregated by Borda, reporting PC/Kendall tau alongside NDCG, and report a popularity baseline and AvgPop/long-tail coverage.
- MovieLens memorisation (2505.10212) means zero-shot LLM numbers on MovieLens can be inflated; using TMDB text with titles masked, or a held-out recent-movie subset, would be a protective ablation. This is my suggestion.

### Gaps
- No 2025-2026 paper found that benchmarks open HuggingFace LLMs (Qwen3, Llama-3.x, Gemma-3) as zero-shot rankers on MovieLens with systematic prompting variants and reports popularity-bias numbers; the closest are 2508.02020 (70B only) and 2606.29947 (reranker as diagnostic).
- Quantified history-order sensitivity numbers (for zero-shot, not fine-tuned LLMs) from 2025-2026 were not retrieved beyond abstracts.
- Many abstracts did not name the LLMs (2608.03091, 2607.24869, 2602.12530); full text not opened.

## Q3. Best recipe for LoRA-tuning a 1B-8B open LLM for recommendation, and GPU memory

### Takeaway
Across 2025-2026 papers the de facto recipe is LoRA rank 16 (alpha 32 or 16) on attention projections, lr 1e-4 to 2e-4 (5e-5 for short listwise tuning), a 1.5-8B instruct model (Llama-3.2-1B/3B, Llama-3.1-8B, Qwen2.5-1.5B/7B, Mistral-7B), and 24 GB GPUs (RTX 4090 / A5000); 4-bit QLoRA lets 1B-8B fit on a single 24 GB card. No paper I read gives a clean memory-vs-rank table, and I found no direct head-to-head of "best LoRA recipe" for recommendation.

### Cited Findings
- **GLoSS: Generative Language Models with Semantic Search for Sequential Recommendation.** Krishna Acharya, Aleksandr V. Petrov, Juba Ziani. arXiv 2506.01910, v1 2 Jun 2025, cs.IR. https://arxiv.org/abs/2506.01910 . **[HTML]** Code https://github.com/krishnacharya/GLoSS
  - LLaMA 3.2 1B/3B and LLaMA 3.1 8B generate a query from the history; item retrieval by semantic search with **e5-small-v2** (33M, d=384; e5-base-v2 and BM25 compared). QLoRA 4-bit, LoRA rank 16, alpha 16 (11M / 24M / 42M adapter params for 1B/3B/8B), 10 epochs, effective batch 16, AdamW lr 1e-4, 300 warmup steps, max context 1024.
  - Data: Amazon Beauty, Toys and Games, Sports and Outdoors (5-core); Recall@5 / NDCG@5 over the full catalogue, leave-last-out. Baselines: SASRec, BERT4Rec, FDSA, S3Rec, TIGER, ActionPiece; P5, GPT4Rec, LlamaRec, E4SRec (numbers copied from papers, not reproduced).
  - Results: Recall@5 Beauty 0.0387 (SASRec) to 0.0681; Toys 0.0463 to 0.0796; Sports 0.0233 to 0.0364. Headline +33.3% / +52.8% / +15.2% Recall@5 vs the best ID baseline.
  - Hardware: single RTX A5000 24 GB; training time not reported. Limitations: LLM recommenders need more VRAM/time than ID models; possible LLaMA-3 memorisation of benchmarks; baselines not reproduced. Usefulness: **HIGH** (explicitly uses e5 + QLoRA on 1B-8B on 24 GB; but Amazon, not MovieLens).
- **Language Models as Semantic Augmenters for Sequential Recommenders (LaMAR).** Mahsa Valizadeh, Xiangjue Dong, Rui Tuo, James Caverlee. arXiv 2510.18046, v1 20 Oct 2025. https://arxiv.org/abs/2510.18046 . **[HTML]** Code https://github.com/mahsavalizadeh/LaMAR
  - GPT-4o-mini / Gemini-1.5-flash generate extra item-text signals; Llama-3.2-3B-Instruct and Qwen2.5-1.5B-Instruct are LoRA-tuned as recommenders. LoRA r=16, alpha=32, dropout 0.1 on q/k/v, lr 2e-4 (Llama) and 1e-4 (Qwen), per-device batch 2 x grad-accum 20 (effective 80). 6 Amazon categories + MovieLens-1M generalisation test. Baselines S3-Rec, ZESRec, UniSRec, Recformer. Hardware: 4x A5000 24 GB for Recformer, 2x A5000 for Llama-3B, one GPU for Qwen.
  - Numbers: Recformer Industrial NDCG@10 0.1052 to 0.1114 (+5.89%); Office Products with LoRA-Qwen NDCG@10 0.6319 to 0.8943 (+41.54%, a very large jump on a small sampled-negatives style setup, treat with caution); ML-1M Recformer NDCG@10 +17.97%. Limitations: some metrics fall, ablations on one dataset, small human study. Usefulness: MED.
- **RecCocktail: A Generalizable and Efficient Framework for LLM-Based Recommendation.** Min Hou, Chenxi Bai, Le Wu, Hao Liu, Kai Zhang, Weiwen Liu, Richang Hong, Ruiming Tang, Meng Wang. arXiv 2502.08271, v1 12 Feb 2025 (v2 30 Oct 2025). https://arxiv.org/abs/2502.08271 . **[ABS]** General "base spirit" LoRA + domain "ingredient" LoRA merged in weight space with entropy-guided weights; no inference overhead; warm and cold-start. Search-snippet details **[SNIP]**: TALLRec baseline, LoRA r=16, alpha=32, dropout 0.05, RTX 4090 24 GB, Qwen2-7B backbone (a snippet; not confirmed on the abstract page). No code link on the abstract page. Usefulness: MED-HIGH (LoRA merging for cold start).
- **ITDR: An Instruction Tuning Dataset for Enhancing LLMs in Recommendations.** Zekun Liu, Xiaowen Huang, Jitao Sang. arXiv 2508.05667, v1 1 Aug 2025. https://arxiv.org/abs/2508.05667 . **[ABS]** About 200K instances from 13 public datasets, 7 subtasks (user-item interaction and understanding); tuning improves GLM-4, Qwen2.5, Qwen2.5-Instruct, LLaMA-3.2; compares against larger closed LLMs. Code https://github.com/hellolzk/ITDR . Usefulness: **HIGH** (ready instruction data for small open models).
- **GraphLoRA: Structure-Aware Low-Rank Adaptation for LLM Recommendation.** Lin Mu, Guoji Wang, Li Ni, Lei Sang, Zhize Wu, Peiquan Jin, Yiwen Zhang. arXiv 2606.07526, v1 20 Apr 2026 (cs.CL; id suggests June, date as fetched). **[HTML]** Vicuna-7B backbone, LoRA rank 8 on q/v, MF d=256 plus 3-layer NGCF; baselines TALLRec, CoLLM, BinLLM, CoRA, LightGCN, NGCF, MF, SASRec; ML-1M, Amazon-Book, Book-Crossing (few-shot); AUC, UAUC, NDCG@10. Code https://github.com/wgj15965/GraphLoRA . Usefulness: MED (TALLRec-style CTR/AUC protocol on ML-1M).
- **When Transformers Meet Recommenders: Integrating SASRec with Fine-Tuned LLMs (SASRecLLM).** Kechen Liu. arXiv 2507.05733, 8 Jul 2025. **[SNIP]** SASRec as collaborative encoder + LoRA LLM + mapping layer; cold-start and warm-start gains; code https://github.com/kechenkristin/RecLLM . Usefulness: MED.
- **REPREC: Representation Driven Parameter-Efficient Recommendation System.** Harshini Kavuru, Dwipam Katariya, Giri Iyengar, Pranab Mohanty, Kalanand Mishra, Raghu Machiraju. arXiv 2607.24845, v1 24 Jul 2026 (page shows v4, 28 Aug 2026). https://arxiv.org/abs/2607.24845 . **[ABS]** Both the sequential encoder and the LLM stay frozen; an MLP injects a fixed-size user embedding as soft tokens; 94-99% of full-history performance when training on short histories; 1.50x per-epoch speed-up. A search summary says its TALLRec baseline reproduces the original recipe (Alpaca warm start on LLaMA-1, LoRA rank 8 on q_proj/v_proj) **[SNIP]**. Code https://github.com/phdbotcode/REPREC . Usefulness: MED (cheap training idea).
- **GradSup: Gradient Superposition for Personalised and Scalable LLM Recommendation.** Dandeniya, Dasanayaka, de Silva, Saltis, Jayatilleke, Mills, Moraliyage. ACM (doi 10.1145/3773078.3831758), 27 Sep 2026. **[SNIP]** TinyLoRA-based closed-form per-user adapters, 15x speed-up over iterative fine-tuning, 400x compression vs full LoRA, on movie/book/electronics; code https://github.com/kanishkaRandunu/GradSup . Usefulness: LOW-MED.
- Low-confidence **[SNIP]**: *Intelligent Recommendation Systems Using Multi-Scale LoRA Fine-Tuning and LLMs* (Zhang et al., IEEE AIBDF 2025, ML-1M); *LLM-Augmented Semantic Resonance System (SRR)* (Venkatesh et al., IEEE CCWC 2026; LoRA Llama 2 13B, ML-25M, +16.4% NDCG@10 over a transfer baseline); *Hybridizing LLMs and Dual-Layer Retrieval ... Gemma 2 (9B) and MovieLens* (Celik and Bilge, UBMK 2025; rating prediction on ML-100K with RAG); *ExplainRec* (Bo Ma et al., arXiv 2511.14770, MovieLens-25M, AUC +0.7%); *Data-Efficient Fine-Tuning for LLM-based Recommendation with Dual-Score Pruning* (Bo Ma et al., IEEE 2025; 1-2% data matching full fine-tuning). I could not verify these and several look weak; do not rely on them.
- **Memory data points actually found:** Qwen3-8B bf16 inference 36 GB peak (2606.29947); QLoRA/LoRA at 1B-8B on a single 24 GB A5000 (2506.01910, 2510.18046); RTX 4090 24 GB (2502.08271, snippet); mpnet-base bi-encoder fine-tune on a free Kaggle Tesla T4 16 GB, FP16, batch 8 x 4 accumulation, 1 epoch about 3 h 40 min (2602.00899, a bi-encoder not an LLM).

### Inferences
- A defensible starting recipe for the thesis: Qwen2.5-1.5B/3B-Instruct or Llama-3.2-1B/3B-Instruct, 4-bit QLoRA, r=16, alpha 16-32, dropout 0.05-0.1, q/k/v (optionally all linear), lr 1e-4 to 2e-4, effective batch 16-80, max length 1024. These values are the intersection of the papers above, not an optimum any paper demonstrates.
- On a free Colab/Kaggle T4 (16 GB), 1-3B QLoRA is feasible; 7-8B QLoRA is borderline and 7-8B bf16 LoRA is not; this is inferred from the 24 GB data points, no paper reports T4 numbers for LLM recommenders.
- ITDR is the most practical source of instruction-tuning data to avoid building templates from scratch.

### Gaps
- No clean ablation on LoRA rank/targets for recommendation; no table of GPU memory vs model size vs sequence length for recommenders.
- TALLRec/BIGRec successors with Qwen3 (2025-2026) not found; BIGRec-style grounding papers from 2025-2026 were not retrieved.
- Training time/GPU hours are mostly unreported.

## Q4. Which baselines do these papers always include?

### Takeaway
Popularity and some form of text-based retrieval baseline (BM25 or sentence-embedding cosine) appear in all cold-start diagnostic studies; trained-model comparisons use SASRec, LightGCN, BPR/MF, TALLRec, CoLLM and, in generative settings, P5/TIGER/LlamaRec. LightFM did not appear in anything I read.

### Cited Findings
- BM25 as the only baseline: 2512.13001. BM25 + zero-shot MPNet: 2602.00899 (BM25 Recall@10 0.26, zero-shot all-mpnet-base-v2 0.42, fine-tuned 0.66 on Amazon Fashion review-to-title retrieval, Kaggle T4).
- Random / Popularity / Embedding Cosine / candidates-only: 2604.16318.
- Popularity, item-kNN, TF-IDF, Markov, BPR, LightGCN, SASRec, SBERT/BGE dense retrieval, frozen two-tower, cross-encoder, RRF: 2606.29947.
- LightGCN as first-stage candidate generator for LLM rerankers: InvariRank 2604.27599 (K=25); the withdrawn 2505.04948 also used LightGCN top-k.
- TALLRec, CoLLM, BinLLM, CoRA, LightGCN, NGCF, MF, SASRec with AUC/UAUC/NDCG@10: 2606.07526.
- SASRec, BERT4Rec, FDSA, S3Rec, TIGER, ActionPiece, P5, GPT4Rec, LlamaRec, E4SRec with Recall@5/NDCG@5 full ranking: 2506.01910.
- Text-embedding baselines in embedding-for-rec papers: BERT, GTE-Qwen2-7B, BGE-large-en-v1.5, LLM2Vec, EasyRec, BLAIR, LLMEmb; downstream GRU4Rec and SASRec: 2506.21579 (LLM2Rec). That paper uses Qwen2-0.5B as default backbone (up to 3B tested), Amazon Games/Arts/Movies in-domain and Sports/Baby/Goodreads out-of-domain, Recall/NDCG@10,20 with full ranking, 3 seeds, A40 48 GB GPUs, code https://github.com/HappyPointer/LLM2Rec , KDD 2025, arXiv 2506.21579 v1 16 Jun 2025 **[ABS + HTML]**. Usefulness: MED-HIGH (shows how to compare against e5/bge/GTE embeddings; LLM-embedding tuning with full fine-tuning of 0.5B).

### Inferences
- Minimum thesis baseline set that matches this literature: Random, Popularity, BM25 on item text, text-embedding kNN (e5/bge/GTE/Qwen3-Embedding), item-kNN / BPR-MF / LightGCN, and SASRec (if sequences used); LightFM would be an extra the literature does not require but which matches the user's "hybrid" framing.

### Gaps
- No evidence for LightFM in any 2025-2026 paper opened.

## Tool notes
- **SciSpace search-papers** (natural-language questions): best for discovering 2025-2026 recsys items quickly (returned dates up to Oct 2026, abstracts, DOIs). Limits: returns many non-arXiv conference/Zenodo items of uneven quality; several results appear to be weak or templated papers (e.g. multiple items by the same author group); some dates are "2023" for 2025-2026-looking works; pre-2025 papers dominate generic queries; no full text. Abstracts only, so always label [SNIP].
- **WebSearch** (standard mode) gave useful follow-up IDs (2604.16318, 2606.29947, 2602.00899, 2604.27599, 2608.03091, 2601.09478, GLoSS, LaMAR, RecCocktail). Its prose summaries sometimes contain errors (e.g. it called 2512.13001 "outside a 2026 window" and misattributed FairLRM to 2505.10212); always confirm against arXiv. US-only, extended mode noticeably more useful than standard for the "2026" query.
- **WebFetch on arxiv.org/abs/** is reliable for title/authors/v1 date/abstract/comments; **arxiv.org/html/<id>** gives full-text details through a small summarising model (numbers can be wrong; re-check before citing); **arxiv.org/pdf/** returns compressed binary the fetcher cannot read; local PDF reading failed (poppler not installed).
- Date oddities seen: 2604.16318 (v1 date says Feb 2026), 2602.00899 (stray August 2026 date), 2606.07526 (v1 date April 2026). Version dates on fetched pages should be cross-checked on arxiv.org/abs/<id>?version.
- Not done: Google Scholar, OpenReview, ACM DL and ACL Anthology direct fetches (only the ACL 2026 PDF URL appeared in search), Hugging Face papers pages, GitHub README checks for GPU numbers. Roughly 50 tool calls were used, above the 15 suggested, because the objective was a dense catalogue.
